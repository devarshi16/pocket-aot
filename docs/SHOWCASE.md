# Photos and video for the repository or a future blog

## Essential captures

1. **Hero photo:** the complete powered setup, LCD sharp, a finger or coin nearby for scale, with a clean background. Frame both landscape and portrait versions.
2. **One-take conversion:** show a local cartridge being imported into Pocket Arcade, the conversion result, clicking Flash, the Pico rebooting, and a short moment of responsive gameplay. Keep the laptop and device in the same wide shot so the connection is clear. Record a separate desktop capture for readable GUI text.
3. **Standalone run:** power the Pico from a power bank, show the cable going to the power bank, then operate the controls. This demonstrates that the compiled game runs on the board independently.
4. **Controls close-up:** show directions, A/B, pause, and the stick's centre press. Button Lab is useful for proving all nine inputs, while an original demo makes the result visually appealing.
5. **Status walkthrough:** a short screen recording moving from the overview to a partial API's limitations and then the game sample. Keep implementation and actual game results visible as separate measures.

## Extra stills

- Front and back of the hardware, with the board model marking, LCD model and connector orientation readable. This helps readers reproduce the build.

- A side-by-side of a desktop reference and the physical display at the same scene, if you have a reference you can run. Label differences honestly.

## Practical recording notes

Use a tripod or prop the phone up. Lock focus and exposure on the LCD; lower exposure until colors retain detail. Use soft room light so the buttons remain visible without reflecting a lamp in the panel. Try 30 and 60 fps, then review for rolling bands or flicker before filming the full sequence. If available, try a fixed shutter setting and keep the best-looking result. Take clean footage without music or captions too, so it remains easy to edit later.

For a compact README clip, aim for 15–30 seconds. Keep a longer 60–90 second conversion-to-play sequence for the blog. Original demo footage can be included directly. Attribute third-party games visible in screenshots or gameplay footage; a screenshot permission does not turn a source-bearing `.p8.png` into a safe image asset.

Place selected media in `docs/media/`. Prefer ordinary PNG/JPEG screenshots and a short compressed MP4 for GitHub uploads. Keep raw camera footage and personal desktop recordings outside the source repository.
